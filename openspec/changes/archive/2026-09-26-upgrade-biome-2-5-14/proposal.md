# Proposal

## Why

The presets, the repository's own configuration, and the README target Biome
2.5.13 while 2.5.14 is current: its eight new rules are unaccounted for, a new
setting on an enabled rule has no decision, its behaviour changes would reach
consumers of all six presets unexplained, and the rule-catalogue drift check stays
switched off until the versions agree. This pass brings all of it level at 2.5.14
and corrects the README count that is already wrong. Intent: `intent.md`.

## What Changes

- **Target Biome 2.5.14.** Advance the `$schema` URL in all six `dist/*.json`
  presets and in `biome.json`, and the seven Biome version references in
  `README.md`. The `@biomejs/biome` devDependency already declares `^2.5.14`
  (PR #212), so `package.json` does not move.
- **Regenerate the rule catalogue** (`audit/rule-metadata.json`) against 2.5.14 —
  538 → 546 rules — which switches the drift check back on.
- **Account for all eight new rules.** All eight are nursery; 2.5.14 removes,
  renames, and moves none, and it directly follows 2.5.13, so there is no
  intermediate release to diff.
  - **Enable six** in `react-strict` at `warn` and in `react-balanced`:
    `noJsonUnsafeValues`, `noObsoleteTags`, `noReturnInFinally`,
    `useConsistentFunctionStyle`, `useConsistentObjectKeys`, `useValidTestTitle`.
    Each one's balanced level is settled in `design.md`, with the evidence behind
    it.
  - **Leave out two** on their published domains, with no ledger entry:
    `noSvelteAtDebugTags` (`svelte`) and `noVueUndeclaredDirectives` (`vue`).
- **Decide `useExhaustiveSwitchCases`'s new `requireExplicitCase` setting** for
  `react-strict` and `react-balanced` independently. The decision and its evidence
  live in `design.md`.
- **Keep the `-stable` presets at their current 180 rules.** Every addition and the
  setting decision sit in `nursery`, which the `-stable` variants drop, so they
  change only in their `$schema` line.
- **Reconcile every count the README publishes** — the nursery category count, the
  preset totals in the ladder prose and the Configurations table, and the balanced
  relaxation table and its totals — and correct the React strict section, whose
  `263` has disagreed with the preset's 274 since the 2.5.13 pass. That sentence is
  reworded so the number it carries describes what it counts.
- **Correct `CLAUDE.md` where it has stopped being true**: its "flag 201 correct
  rules" figure is already 212 today and would be 217 after this pass.
- **Release a `minor`** whose changeset names each of the eight new rules — the six
  enabled and the two left out, with the reason — every balanced relaxation, the
  `requireExplicitCase` decision, and each inherited 2.5.14 behaviour change a
  consumer would notice, grouped by the presets it reaches.
- **Audit configuration migrations** by previewing `biome migrate` against every
  preset and `biome.json`, so that no consumer needs a configuration change for the
  upgraded presets to keep working.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. The standing requirements in `linter-rule-coverage` govern this pass
unchanged (intent — Constraints): it applies them to 2.5.14 without altering any.
The change therefore sets `skip_specs: true` rather than inventing a requirement to
satisfy validation.

## Impact

- `dist/biome.react-strict.json`, `dist/biome.react-balanced.json` — six nursery
  entries each, the `useExhaustiveSwitchCases` decision, and `$schema`.
- `dist/biome.recommended.json`, `dist/biome.react-recommended.json` — `$schema`
  only.
- `dist/biome.react-strict-stable.json`, `dist/biome.react-balanced-stable.json` —
  regenerated by `pnpm sync-stable`; `$schema` only.
- `biome.json` — `$schema`.
- `audit/rule-metadata.json` — regenerated. `audit/rule-exclusions.json` —
  unchanged.
- `README.md` — version references, counts and totals, the relaxation table, and
  the React strict sentence.
- `CLAUDE.md` — one sentence.
- `.changeset/` — one `minor` changeset.
- Not touched: `package.json`, `pnpm-lock.yaml`, `scripts/`, and the standing
  specs.
- Consumers: users of `react-strict` and `react-balanced` receive the six rules as
  new diagnostics; users of every preset receive 2.5.14's formatter, parser, and
  rule-behaviour changes.
