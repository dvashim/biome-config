Target Biome 2.5.14 and add six nursery rules

- **`react-strict` and `react-balanced` now require Biome 2.5.14 or later.** They name six rules and one rule option that Biome 2.5.13 does not know, and 2.5.13 refuses to load them: it stops with `Found an unknown key` before linting anything. Upgrade `@biomejs/biome` together with this package. The other four presets list no new rules.
- **Inherited from Biome — formatter output changes, so every preset.** Multiline template-literal interpolations keep their closing brace's indentation when the source indentation is not a multiple of the tab width. Own-line comments before a binary operator now stay above it, which matters here because all six presets set `operatorLinebreak: "before"`. A leading comment that forces type arguments onto several lines now gets a newline before the closing `>`. Multiline expressions after operators such as `!` no longer gain extra parentheses or moved comments, and unary operands with leading line comments lose redundant parentheses. In HTML, which all six presets format via `html.experimentalFullSupportEnabled`: line breaks between CJK characters are preserved instead of becoming spaces; PascalCase components such as `<Body>` in Vue, Svelte and Astro files are no longer formatted as the native element; unknown elements named like SVG elements are no longer block-formatted; and `<listing>` loses its special handling. `suite()` calls are now formatted as test declarations, like `describe()`.
- **Inherited from Biome — parser.** A TypeScript class member that combines `readonly` and `accessor`, in either order, now reports an error, as does `accessor override`; `override accessor` now parses.
- **Inherited from Biome — recommended rules, so every preset.** `useAnchorContent` now reports anchors without accessible content in HTML, Astro, Vue and Svelte files even when they carry `aria-label`, `aria-labelledby` or `title`, matching its JSX behaviour, so **expect new diagnostics** there. `noUselessFragments` (fragments with props in Astro), `noDescendingSpecificity` (no longer compares selectors across separate cascade layers) and `noUnusedImports` (type-only imports used in computed names of declared class properties) report less.
- **Inherited from Biome — which files and fixes Biome touches, so every preset.** With `vcs.useIgnoreFile`, which all six presets enable, files re-included by a negation pattern in a nested `.gitignore` are now linted and formatted even when that file contains `*`, so files that were silently skipped may start reporting. `check --write` and `lint --write` now apply fixes inside HTML attribute expressions, such as a Svelte `onclick={…}` handler, where they previously reported a fix and changed nothing. Suppressions targeting the whole `assist` category, such as `biome-ignore-all assist`, are now respected. In editors, `source.fixAll.biome` no longer formats a file with parse errors, because these presets set `formatWithErrors: false`. Test rules now treat `suite`, `fsuite`, `xsuite` and `test.suite` blocks like `describe`. The Vue, Svelte and Astro changes reach you whenever you have such files, even though these presets exclude those frameworks' rules.
- **Inherited from Biome — opt-in rules listed in stable categories.** These reach `react-strict`, `react-balanced` and both `-stable` variants, but not `recommended` or `react-recommended`. `useReadonlyClassProperties` now also reports static properties that are never reassigned, so **expect new diagnostics**. The fix from `useConsistentArrowReturn` now parenthesizes returned expressions that begin with an object literal, and the fix from `useSimplifiedLogicExpression` now keeps the line breaks in multiline conditions with line comments; both previously could produce broken code. Fewer false positives from `noUselessStringConcat`, `noNoninteractiveElementInteractions` (native `<dialog>`), `noUnknownAttribute` (fullscreen handlers, `credentialless`, `maskType` with React 19.3 or later), `useUniqueElementIds` (static IDs inside SVG), `useHookAtTopLevel`, `useSingleJsDocAsterisk`, and `noUndeclaredVariables` (aliased imports in Vue single-file components).
- **Inherited from Biome — nursery rules these presets list**, so `react-strict` and `react-balanced` only. **New diagnostics** from `useIncludes` (now also `lastIndexOf()` comparisons and `some()` with a strict-equality callback), `useExhaustiveSwitchCases` (`for…of` over a class property; literal unions derived from `(typeof values)[number]` and `keyof typeof object`) and `noFloatingPromises` (promises returned through generic method signatures, including Playwright fixtures). `useConsistentTestIt` now rewrites imports along with calls; `noUndeclaredCustomProperties` no longer hangs on stylesheets imported from JavaScript; Tailwind classes with dashed base names such as `border-bs` parse correctly; and `useTailwindShorthandClasses` and `useExhaustiveSwitchCases` each drop a false positive.
- **Six new nursery rules**, `warn` in `react-strict`: `noJsonUnsafeValues` (JSON numbers and strings that parse differently across tools, such as integers beyond 2^53 or lone surrogates), `noObsoleteTags` (obsolete HTML elements such as `<font>` and `<center>`, in HTML and JSX), `noReturnInFinally` (a `return` inside a `Promise#finally()` callback), `useConsistentFunctionStyle` (function declarations versus function expressions), `useConsistentObjectKeys` (JSON keys in one Unicode normalization form), and `useValidTestTitle` (empty, padded or non-string test titles). `useValidTestTitle`'s safe fix trims padded titles under `biome check --write`; `useConsistentObjectKeys` has an unsafe fix.
- **Two of them are relaxed in `react-balanced`**, as established by fixtures run against 2.5.14. `useConsistentFunctionStyle` → **off**: under its default `"expression"` style it reports every function declaration that is not a default export — helpers, hooks and named-export components alike, which is the form React's own documentation uses. Which style to follow is a project's choice; set the rule's `style` option to enforce one. `useValidTestTitle` → **info**: listing it defeats its test-framework gate (it reported identically with and without `vitest` installed), but it only matches test blocks. Inside them, it reports any non-literal title, such as a string variable or `Foo.name`, as not a string, and no option exempts that.
- **`useExhaustiveSwitchCases` sets `requireExplicitCase: true` in `react-strict`.** Both presets also list `useDefaultSwitchClause`, which requires a `default` clause in every switch. Under Biome's default for the new option, a `default` clause makes a switch exhaustive, so on code that satisfies `useDefaultSwitchClause`, `useExhaustiveSwitchCases` could never report a missing case. With the option set, strict reports the union members a switch leaves to `default`; complete switches and switches over non-union types are unaffected. `react-balanced` keeps Biome's default, accepting a `default` that deliberately covers the remaining members.
- **Excluded: `noSvelteAtDebugTags` and `noVueUndeclaredDirectives`** (both nursery). Their only domains are `svelte` and `vue`, which these presets exclude.
- **Counts move asymmetrically.** `react-strict` and `react-balanced` go from 274 to 280 explicit rules (nursery 94 → 100), and balanced relaxations from 22 to 25. Both `-stable` variants are **unchanged — the same 180 rules and 15 relaxations** — because every addition and every new relaxation is in nursery, which `-stable` strips.
- **README correction.** The React strict section said the preset adds 263 rules; it had listed 274 since the previous release. It now gives the preset total, 280, and says what that number counts: every in-scope optional and nursery rule, plus deliberate overrides of recommended ones.
