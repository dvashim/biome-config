Target Biome 2.6.2: load under Biome 2.6, add 27 nursery rules, and carry the rules it promotes

- **All six presets now require Biome 2.6.2 or later.** Biome 2.6 removed the `javascript.parser.gritMetavariables` setting that every preset carried, and it refuses a rule listed under a group the rule has left. Under 2.6, version 1.20.0 of this package stops with `Found an unknown key` before checking anything — and the `^2.5.15` install range the README gave already resolves to 2.6.2. This release loads under 2.6.2 and under no 2.5 release: `recommended` and `react-recommended` now carry a `markdown` setting Biome 2.5 does not know, and the other four list rules under groups 2.5 does not have them in. Upgrade `@biomejs/biome` together with this package. Biome 2.6.0 and 2.6.1 were published to npm without their platform binaries and do not run; use 2.6.2.
- **Settings in your own configuration that stop loading under 2.6.** A promoted rule you configure under `nursery` (for example `"nursery": { "noReactStringRefs": "off" }`), `useSortedClasses` — renamed `useTailwindSortedClasses`, whose `attributes` and `functions` options moved to a top-level `tailwind` section — and `javascript.parser.gritMetavariables`. `biome migrate --write` rewrites the first two in your own `biome.json`; remove the third by hand.
- **Inherited from Biome — new files, so every preset.** Biome 2.6 formats and lints Markdown and SCSS, formats YAML — `pnpm-lock.yaml` and CI workflow files included — and parses `.gs` (Google Apps Script) and `.htm` files, none of which 2.5.15 processed. Expect `biome check` and `biome ci` to report formatting differences in those files, and the fenced code in your Markdown to be reformatted with these presets' JavaScript settings. To keep Biome off any of them, exclude them in your own `biome.json`, for example `"files": { "includes": ["**", "!**/*.md", "!**/pnpm-lock.yaml"] }`.
- **Markdown front matter stays intact.** Under Biome 2.6's default, `biome check --write` reads the front matter that opens a Markdown file as prose: a Changesets file's front matter becomes a `##` heading, and nested front-matter keys lose their indentation. All six presets now set `"markdown": { "parser": { "frontmatter": true } }`, which keeps front matter intact; Biome then only normalizes the quotes inside it.
- **Inherited from Biome — promoted rules that `recommended` and `react-recommended` now run.** Biome 2.6 promoted 59 nursery rules to stable groups. Twelve of them are recommended for the React, test, Playwright, React Native and Drizzle domains, so these two presets now run them at Biome's default severity wherever the domain is on — `react-recommended` turns on `react` itself, and Biome turns the others on from your dependencies. Ten report at `error`: `noComponentHookFactories`, `noJsxNamespace`, `useReactAsyncServerFunction`, `noPlaywrightMissingAwait`, `usePlaywrightValidDescribeCallback`, `noReactNativeRawText`, `useReactNativePlatformComponents`, `noReactNativeDeepImports`, `noDrizzleDeleteWithoutWhere` and `noDrizzleUpdateWithoutWhere`; `noReactStringRefs` and `noIdenticalTestTitle` report at `warn`. `useMathMinMax` and `useDomNodeTextContent` now run in these presets too, at `warn`. The other four presets keep the twelve at `warn`.
- **Inherited from Biome — promoted rules that every preset now runs.** Wherever your dependencies turn on the `vue` or `qwik` domain, the seven promoted Vue and Qwik rules Biome recommends now run, most at `error`, and `noDuplicateFieldDefinitionNames` now runs on GraphQL files. These presets do not list them; turn one off by category if you need to.
- **`react-strict-stable` and `react-balanced-stable` gain 48 rules.** The promoted rules the parents list move to their new stable groups at the same `warn` level, so they now reach the `-stable` variants: all 11 Playwright rules, the Drizzle, React Native and testing rules, React's `noComponentHookFactories`, `noJsxNamespace`, `noJsxLeakedDollar`, `noReactStringRefs` and `useReactAsyncServerFunction`, and `useIframeSandbox`, `noDuplicateSelectors`, `noInlineStyles`, `useImportsFirst` and `useBaseline` among others. No rule changes level in `react-strict` or `react-balanced`.
- **27 new nursery rules**, `warn` in `react-strict`: `noAccidentalBitwiseOperators`, `noArgumentsCallerOrCallee`, `noDoubleComparison`, `noExcessiveStatementsPerFunction`, `noInvalidThis`, `noNestedSwitch`, `noNestedTemplateLiterals`, `noObjectConstructor`, `noOctal`, `noProcessExit`, `noPromiseExecutorReturn`, `noTailwindLegacyUtilities`, `noTailwindRestyledComponents`, `noUnsafeUnaryMinus`, `noUselessAssignment`, `noUselessCall`, `noUselessDateGetTime`, `noZeroFractions`, `useBigintLiterals`, `useCapitalizedConstructors`, `useConsistentJsonFileRead`, `useLowercaseTestTitle`, `useMatchingFunctionName`, `useNamedFunction`, `useSimplifiedBooleanReturn`, `useTailwindStaticClassStrings` and `useUnaryMinus`. Each was run against fixtures under 2.6.2. Worth knowing before you upgrade: `noPromiseExecutorReturn` reports the `new Promise((resolve) => setTimeout(resolve, ms))` sleep idiom (brace the executor), `useCapitalizedConstructors` reports capitalized library calls such as `Schema.Struct({})` and `Intl.NumberFormat()` without `new`, and the Tailwind and test rules run whether or not `tailwindcss` or a test framework is declared.
- **Five of them are turned off in `react-balanced`**; the other 22 stay at `warn`. `noExcessiveStatementsPerFunction` → **off**: its default of ten statements reports an ordinary hook-using component and any `describe` with more than ten tests. `noTailwindLegacyUtilities` → **off**: outside Tailwind v4 it reports class names Tailwind once used, such as Bootstrap's `flex-grow-1`. `noTailwindRestyledComponents` → **off**: it reports every appearance utility passed to a component, a design-system policy, the ground on which balanced already turns `noTailwindRawColors` off. `useLowercaseTestTitle` → **off**: it reports the `describe('ComponentName')` convention, and its fix lowercases the component name. `useTailwindStaticClassStrings` → **off**: it reports every class string assembled from fragments, Tailwind or not, such as `'btn-' + variant`.
- **Watch `noTailwindLegacyUtilities` in `react-strict`.** Its fix is marked safe, so `biome check --write` applies it — and in a project that is not on Tailwind v4 it rewrites class names that only look like Tailwind's: Bootstrap's `flex-grow-1 flex-shrink-0` became `grow-1 shrink-0`. Unless you use Tailwind v4, turn it off by category: `"nursery": { "noTailwindLegacyUtilities": "off" }`.
- **Renamed and removed entries.** `useSortedClasses` is now `useTailwindSortedClasses`, still `warn` in both parents: it follows Tailwind v4's class order, reads the top-level `tailwind` settings, and now also checks HTML-ish files. `useMathMinMax` and `useDomNodeTextContent` leave the lists, because Biome's recommended set now runs them at the same `warn`.
- **Excluded: 23 new rules** (all nursery). Eighteen serve only Vue or Svelte, whose rules these presets exclude: `noSvelteAddEventListener`, `noSvelteClassDirective`, `noSvelteInspect`, `noSvelteObjectInTextMustaches`, `noSvelteUselessDerivedBy`, `noVueBooleanDefault`, `noVueLifecycleAfterAwait`, `noVueRequiredPropWithDefault`, `noVueRootVIf`, `noVueShadowNativeEvents`, `noVueVHtml`, `noVueVText`, `useConsistentBlockLang`, `useSvelteKitResolve`, `useSvelteReactiveClasses`, `useSvelteShorthandDirective`, `useVueConsistentEventHyphenation` and `useVueMatchingComponentFileName`. Five lint Markdown or YAML, languages whose rules these presets do not cover: `noDuplicateMapKeys`, `useConsistentHeadingLevel`, `useFencedCodeLanguage`, `useSingleTopLevelHeading` and `useTopLevelHeading`.
- **Counts.** `react-strict` and `react-balanced` go from 288 to 313 explicit rules (nursery 108 → 85), the `-stable` variants from 180 to 228, and balanced relaxations from 28 to 33. The 15 relaxations in stable groups — the ones `react-balanced-stable` applies — are unchanged.
- **Inherited from Biome — recommended rules, so every preset.** `noUnreachable`, `noUnreachableSuper`, `useGetterReturn`, `useIterableCallbackReturn` and `noFallthroughSwitchClause` now analyze functions that contain a `break` or `continue` inside a labeled loop, and `for (;true;)` loops count as infinite, so **expect new diagnostics**. More from `noSelfAssign` (the same property written with dot and bracket notation), `noDescendingSpecificity` (nested selectors) and `noProto`; fewer from `noConfusingVoidType` (`void | never`), `noTsIgnore` (comments that only mention `@ts-ignore`), `noIrregularWhitespace` (CSS strings), `noDuplicateFontNames` (`monospace, monospace`), and `noUnusedVariables` and `noUnusedImports` on Svelte and Vue files. The fix of `noAdjacentSpacesInRegex` no longer changes what a character class matches.
- **Inherited from Biome — formatter and parser, so every preset.** CSS-in-JS templates with interpolations, such as styled-components and Emotion, are now formatted, because all six presets set `javascript.experimentalEmbeddedSnippetsEnabled`. A sequence expression after `return` or `throw` gains parentheses. CSS comments no longer shift indentation, comments inside spread JSX objects are no longer duplicated, Vue directive values and event handlers are now formatted, Vue's `generic` attribute parses, and Svelte and Astro templates get parser and formatter fixes.
- **Inherited from Biome — opt-in rules listed in stable groups.** These reach `react-strict`, `react-balanced` and both `-stable` variants. `noEmptySource` now reports Markdown files that hold only blank lines and comments, and YAML documents with no content. The CSS rules these presets list now apply to `.scss` files, and `useStrictMode` to `.gs` files. More from `useArraySortCompare` (`sort()` on unannotated array literals), `noUnnecessaryConditions` and the other type-aware rules (mapped types and template literals now infer), and `noDuplicateSelectors` (nested `@container` and `@starting-style` blocks); fewer from `noUnknownAttribute` (React 19 transition handlers), `noUndeclaredVariables` (Vue `generic` parameters) and `useConsistentObjectDefinitions` (named function expressions). `useNamingConvention`'s safe fix no longer renames declarations in nested ambient namespaces, the fix of `noUselessStringConcat` now stringifies numbers correctly, and `noRestrictedElements` now covers HTML, Vue, Svelte and Astro files once you configure it.
- **Inherited from Biome — nursery rules these presets list**, so `react-strict` and `react-balanced` only. More from `noFloatingPromises`, `noMisusedPromises`, `noUselessTypeConversion` and `useExhaustiveSwitchCases`, through the same inference work. The Tailwind class parser handles more class shapes, `useTailwindShorthandClasses` no longer suggests behavior-changing shorthands, and `useBetterDomTraversing` now offers its fix before a comment. In `react-strict` only, because `react-balanced` turns these off: `useLogicalProperties` also checks physical values and now has a fix, `useReactCompiler` analyzes files that export types, `noTailwindArbitraryValue` no longer reports arbitrary modifiers, and `noTailwindRawColors` suggests colors from your theme and scans the project.
