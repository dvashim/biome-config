"@dvashim/biome-config": minor

Target Biome 2.5.15 and add eight nursery rules

- **`react-strict` and `react-balanced` now require Biome 2.5.15 or later.** They name eight rules that Biome 2.5.14 does not know, and 2.5.14 refuses to load them: it stops with `Found an unknown key` before linting anything. Upgrade `@biomejs/biome` together with this package. The other four presets list no new rules.
- **Inherited from Biome — configuration handling, so every preset.** Errors in a configuration file are no longer silently ignored: Biome now stops on them before running, so a configuration of your own that 2.5.14 accepted despite errors may now fail. All six presets load cleanly. A domain set to `"none"` no longer turns off rules a configuration enables explicitly, or rules shared with another enabled domain: if you silenced rules these presets list — such as `noImgElement` in a project that is not Next.js — with `"domains": { "next": "none" }`, they come back, so turn the rule off by category instead, as the README's FAQ shows. And `noTailwindArbitraryValue` loses its `attributes` and `functions` options: a configuration that sets either now fails to load with `Found an unknown key`. No preset sets them.
- **Inherited from Biome — formatter output changes, so every preset.** Multiline Astro expressions in templates and attribute values are now indented at the column of the surrounding markup, and `biome format` formats them too. Comments around Svelte blocks are no longer duplicated, a comment at the end of a block's contents is indented with that content, and `biome check --write` no longer adds invalid parentheses around Svelte `{@const}` declarations. The HTML formatter no longer drops the space between text and an inline element it joins onto the same line. All six presets format HTML-family files via `html.experimentalFullSupportEnabled`.
- **Inherited from Biome — parser.** HTML now reports a mismatched closing tag (`</span>` in `<p>two</span></p>`) and a stray closing tag at the top level as errors, where the formatter previously deleted everything after them; tag names now match case-insensitively. Because all six presets set `formatWithErrors: false`, such files are now reported instead of formatted. Astro frontmatter containing a regex that starts with `>` no longer swallows its closing fence. In TypeScript, `<<` followed by a later `>>>`, and `f<T> << f<T>`, now parse as TypeScript does. Typed slot props in Vue files no longer report a parse error.
- **Inherited from Biome — recommended rules, so every preset.** `noUnusedVariables` now reports expression-bodied arrow functions that only reference themselves, such as `let h = () => h();`, so **expect new diagnostics**, and it counts types used in Vue slot-prop annotations as used. `noUnreachable` and `useGetterReturn` now treat `while` and `do…while` loops with truthy literal conditions as infinite. `noUnknownTypeSelector` (view transition names) and `noUnknownProperty` (`frame-sizing`) report less. The safe fix of `noOctalEscape` no longer changes a string's value, and the fix of `useRegexLiterals` no longer escapes an already escaped slash.
- **Inherited from Biome — which files Biome touches and what it suppresses, so every preset.** With `vcs.useIgnoreFile`, which all six presets enable, parent-directory patterns now apply to child paths, so a re-included directory is kept while its excluded siblings are ignored. Suppression comments now work throughout HTML-ish files and in snippets embedded in JavaScript. The Astro, Svelte and Vue changes reach you whenever you have such files, even though these presets exclude those frameworks' rules.
- **Inherited from Biome — opt-in rules listed in stable categories.** These reach `react-strict`, `react-balanced` and both `-stable` variants, but not `recommended` or `react-recommended`. Fewer diagnostics from `useSimplifiedLogicExpression` (boolean literals on the right of `||` and `&&` outside boolean contexts), `useNamingConvention` (a `namespace` inside `declare global` or an external module declaration, which its safe fix used to rename), `noUndeclaredVariables` (Vue slot props), `noFocusedTests` (chained calls such as `builder.image(url).fit("max")`, and ordinary methods named `test`, `it` or `describe`), `useForOf` (loops that update their index in the body) and `noUnnecessaryConditions` (optional chaining on `RegExp.exec()` results). `noUnnecessaryConditions` also **newly reports** through nested generic type aliases. The safe fix of `noUselessStringConcat` now escapes embedded double quotes, and `noUselessReturn` no longer offers a safe fix that produced invalid code. More accurate type inference reduces false positives across the type-aware rules.
- **Inherited from Biome — nursery rules these presets list**, so `react-strict` and `react-balanced` only. `useReactCompiler` now runs whatever React version `package.json` declares, or none: Biome 2.5.14 ran it only when React 19 or newer was declared, so `react-strict` users on React 18, or without React in `package.json`, now get its diagnostics on files that define components or hooks. It stays `off` in `react-balanced`. `noTailwindArbitraryValue` (strict only; `off` in balanced) now uses the same Tailwind detection as `useTailwindShorthandClasses`: it newly reports `tw` tagged templates and no longer reports `classNames()` calls. Tailwind classes are now also detected in Svelte, Vue and Astro class expressions that use no merging function, which reaches `useTailwindShorthandClasses` and, in strict, `noTailwindArbitraryValue`. **New diagnostics** from `useExhaustiveSwitchCases` (values created with the mapping overload of `Array.from`), and possibly from `noRestrictedDependencies`, whose replacement data was refreshed. `useValidTestTitle` no longer mistakes ordinary method calls named `test`, `it` or `describe` for tests, and `noFloatingPromises` and `noMisusedPromises` no longer overflow the stack on generic types in files that import each other.
- **Eight new nursery rules**, `warn` in `react-strict`: `noMeaninglessVoidOperator` (`void` applied to a call that already returns nothing), `noMisplacedListElements` (`<li>` outside `<ul>`, `<ol>` or `<menu>`, in JSX and HTML), `noReactObjectTypeAsDefaultProp` (array, object and function default props in React components, which create a new value on every render), `noSelfImport` (a module that imports itself), `noTailwindRawColors` (Tailwind palette colors such as `bg-pink-500`), `useLogicalProperties` (CSS logical properties instead of physical ones), `usePromiseRejectErrors` (Promise rejection reasons that are not `Error` objects) and `useStrictBooleanExpressions` (truthiness checks on nullable booleans, strings and numbers). Only `noMeaninglessVoidOperator` has a fix, and it is unsafe. `noReactObjectTypeAsDefaultProp` and `noTailwindRawColors` defeat their framework gates: they reported identically with and without `react` or `tailwindcss` declared.
- **Three of them are turned off in `react-balanced`**, as established by fixtures run against 2.5.15; the other five stay at `warn`. `noTailwindRawColors` → **off**: it reports every palette color, which is Tailwind's default way to color, and whether to require design-system color names is the project's choice — the ground on which balanced already turns `noTailwindArbitraryValue` off. `useLogicalProperties` → **off**: it reports every physical property, `width` and `height` included, so effectively every stylesheet; writing-mode support is the project's choice. `useStrictBooleanExpressions` → **off**: it reports every truthiness check on an optional boolean or string, the idiomatic optional-prop test, and has no option to narrow it; in JSX, `noLeakedRender` (`error` in both presets) still reports the `count && …` zero render it would catch.
- **Excluded: `noAstroConflictingSetDirectives`, `noSvelteExportLet` and `useSvelteKitRuneImports`** (all nursery). Their only domains are `astro` and `svelte`, which these presets exclude.
- **Counts.** `react-strict` and `react-balanced` go from 280 to 288 explicit rules (nursery 100 → 108), and balanced relaxations from 25 to 28. Both `-stable` variants are **unchanged — the same 180 rules and 15 relaxations** — because every addition and every new relaxation is in nursery, which `-stable` strips.
- **README correction.** The React highlights said `useReactCompiler` stays silent unless `react` is an actual dependency. Under Biome 2.5.15 that is no longer true; the highlight now says it runs like the other framework rules, skipping files that define no component or hook.
