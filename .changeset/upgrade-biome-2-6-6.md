Target Biome 2.6.6: add 70 nursery rules from Biome 2.6.3–2.6.6, and bring SCSS rules into scope

- **`react-strict` and `react-balanced` now require Biome 2.6.6 or later.** They list rules that only 2.6.6 declares, so under any earlier 2.6 release they stop with `Found an unknown key` before checking anything: 11 unknown keys under 2.6.5, 70 under 2.6.2. Upgrade `@biomejs/biome` together with this package. Avoid 2.6.5 in particular: once its `nursery` group passed 256 rules, configuring a rule near the end of the group could switch a different rule on or off (enabling `useWhileLoopCondition` enabled `noDanglingUnderscore` instead). 2.6.6 fixes that. `recommended`, `react-recommended` and both `-stable` variants change no rule and still load under 2.6.2–2.6.5. There they print an information notice that the configuration schema version does not match the CLI version, which fails nothing.
- **70 new nursery rules**, all at `warn` in `react-strict`: `noArrayForEach`, `noArrayMethodsOnArguments`, `noArraySortForMinMax`, `noAwaitInPromiseMethods`, `noBooleanSortComparator`, `noChainedComparison`, `noConsoleSpaces`, `noConstantComparisons`, `noDanglingUnderscore`, `noDynamicDelete`, `noEagerArrayMethodsInLoops`, `noErasingOperation`, `noExcessiveNestedBlocks`, `noInvalidRemoveEventListener`, `noLateEventControl`, `noMagicArrayFlatDepth`, `noMapSpread`, `noMismatchedMapKey`, `noMissingScssInterpolation`, `noMissingThrow`, `noNegatedArrayPredicate`, `noNewRequire`, `noNull`, `noNumberArgumentOutOfRange`, `noObjectLiteralComparison`, `noObsoleteAttributes`, `noPathConcat`, `noPlaywrightNthMethods`, `noPlaywrightUnsafeReferences`, `noPseudoElementInFunctionalPseudoClass`, `noReturnArrayPush`, `noSelfNestedLayer`, `noSharedBranchCode`, `noShortTimeValues`, `noSinglePromiseInPromiseMethods`, `noSubtractionComparison`, `noSyncMethods`, `noTanstackQueryRestDestructuring`, `noTanstackQueryVoidQueryFn`, `noUninvokedArrayCallback`, `noUnnecessaryStringTrim`, `noUnreadableForOfExpression`, `noUnreadableIife`, `noUnsafeReturn`, `noUselessAwait`, `noUselessLengthCheck`, `noUselessRecursion`, `noUselessSplice`, `noUselessTypeAssertion`, `noZeroLengthUnit`, `useAccessorPairs`, `useBlockStatementOverIife`, `useConsistentLightnessNotation`, `useConsistentUnicodeBom`, `useExpectToContain`, `useIteratorZip`, `useMathAbs`, `useMathTrunc`, `useNextScriptForGoogleAnalytics`, `useObjectFromEntries`, `usePackageJsonCpu`, `usePackageJsonEngines`, `usePackageJsonValidCpu`, `usePackageJsonValidEngines`, `useReactNativeValidPlatformColors`, `useSetSize`, `useTailwindVariablesShorthand`, `useTanstackQueryInfiniteQueryPropertyOrder`, `useTanstackQueryStableQueryClient` and `useWhileLoopCondition`. Each was run against fixtures under 2.6.6. Worth knowing before you upgrade:
  - `useConsistentUnicodeBom` reports a leading byte order mark in JavaScript, TypeScript, CSS, JSON, HTML and Markdown files alike.
  - `noShortTimeValues` reports nothing until you set its `minimum`.
  - `usePackageJsonEngines` and `usePackageJsonCpu` require those fields in every `package.json`.
  - Like the other framework rules in these presets, the new Playwright, TanStack Query, Next.js, React Native, Tailwind and test rules run whether or not you depend on that framework.
- **Ten of them are relaxed in `react-balanced`**; the other 60 stay at `warn`.
  - `noArrayForEach` → **off**: it reports every `forEach` call, and `noForEach` already reports those that ignore the index.
  - `noDanglingUnderscore` → **off**: it reports `_`-prefixed variables and property access such as `user._id`.
  - `noNull` → **off**: it reports React's own `return null` and nullable state.
  - `noPlaywrightNthMethods` → **off**: it reports `.first()` and `.last()` on any object, such as Cheerio selections and Immutable lists, not only Playwright locators.
  - `noSyncMethods` → **off**: it reports React DOM's `flushSync` and every `*Sync` call in scripts and configuration files.
  - `useIteratorZip` → **off**: it suggests `Iterator.zip()`, which Node.js 26 does not provide.
  - `useNextScriptForGoogleAnalytics` → **off**: it reports a Google Analytics `<script>` in any React app and recommends Next.js' own component.
  - `usePackageJsonCpu` → **off**: only packages that ship native binaries declare a `cpu` field.
  - `useTailwindVariablesShorthand` → **off**: see the next item.
  - `usePackageJsonEngines` → **info**: a private app's manifest needs no `engines` field.
- **Watch `useTailwindVariablesShorthand` in `react-strict`.** Its fix is marked safe, so `biome check --write` applies it, and it rewrites `bg-[var(--brand)]` to Tailwind v4's `bg-(--brand)` even when `tailwindcss` 3 is declared. Tailwind v3 does not understand that syntax, and the style is lost. Unless you use Tailwind v4, turn it off by category: `"nursery": { "useTailwindVariablesShorthand": "off" }`.
- **Two more caveats in `react-strict`.** `noArrayForEach` and the existing `noForEach` both report a `forEach` call that ignores its index, so each such call gets two warnings; turn either off by name. `useIteratorZip` steers code toward `Iterator.zip()`, which current Node.js releases lack, so follow it only where a polyfill runs.
- **SCSS rules are now in scope.** Biome already lints and formats `.scss` files for every preset. `noMissingScssInterpolation`, the first rule documented only in SCSS, is listed. It reports a Sass variable or function call written into a custom property without `#{}`, which the browser would receive as literal text such as `$gap`.
- **Excluded: 90 new rules** (all nursery). 84 serve only Vue, and 5 only Svelte (`noSvelteBindValueOnCheckableInputs`, `noSvelteIgnoredUnsubscribe`, `noSvelteInternal`, `useSvelteEventDispatcherTypes` and `useSvelteStoreInitialValue`); these presets exclude both frameworks' rules. `noYamlBooleanKeys` lints YAML, a language whose rules these presets do not cover.
- **Counts.** `react-strict` and `react-balanced` go from 313 to 383 explicit rules (nursery 85 → 155), and balanced relaxations from 33 to 43. The `-stable` variants keep their 228 rules and the 15 relaxations `react-balanced-stable` applies, because every new rule is in `nursery`.
- **Inherited from Biome, through the formatter and parser, so every preset.**
  - TypeScript output keeps parentheses that changed meaning or did not parse when dropped, around instantiation expressions, optional chains followed by `!` or type arguments, and `new` callees that contain `import()`.
  - Markdown formatting gets about fifteen fixes: blank lines between blocks, list and blockquote nesting, table idempotency, and wrapping inside emphasis.
  - SCSS prints comma-separated multi-value declarations one per line.
  - Biome no longer processes `pnpm-lock.yaml`.
  - `.editorconfig` sections with nested or bracketed globs now apply, because these presets set `useEditorconfig`.
  - The run summary now goes to stderr.
- **Inherited from Biome, through recommended rules, so every preset.**
  - `noInvalidGridAreas` counts cells instead of characters, so it reports different `grid-template-areas` rows.
  - `noShorthandPropertyOverrides` recognizes more overrides.
  - `noUnknownProperty` checks SCSS nested properties by the name Sass emits.
  - Fewer reports from `useDomNodeTextContent`, `noDescendingSpecificity`, `useMathMinMax` and `useGenericFontNames`.
- **Inherited from Biome, through opt-in rules these presets list.**
  - `react-strict`, `react-balanced` and both `-stable` variants:
    - fewer reports from `noUselessElse` (an `if` that ends with a `switch` without `default`) and from `usePlaywrightValidDescribeCallback`;
    - one diagnostic per repeated title from `noIdenticalTestTitle`;
    - `useNamingConvention`'s `typeMember` selector no longer applies to type parameters;
    - `useConsistentTestIt`'s fix no longer leaves an unused import.
  - `react-strict` and `react-balanced` only:
    - more reports from `useExhaustiveSwitchCases` and from `noMisusedPromises`, which now also checks Promise-returning callbacks passed to `find` and `every`;
    - fewer from `noBaseToString`;
    - the Tailwind class parser accepts more unknown utilities.
  - `react-strict` only, because `react-balanced` turns these off:
    - `useLogicalProperties` also reports multi-value physical shorthands and combinable logical pairs;
    - `noTailwindRawColors` gains an `allowBlackAndWhite` option whose default keeps its behaviour.
