Target Biome 2.5.13 and add eleven nursery rules

- **Inherited from Biome — type-aware rules get better, and louder.** Type inference now derives an unannotated callback parameter's type from the signature of the function it is passed to, honours explicit type arguments on calls, and stops over-resolving namespace imports and imported generics. That improves `noFloatingPromises`, `noMisusedPromises`, `noBaseToString`, `useNullishCoalescing`, `useRegexpExec`, `noUnnecessaryConditions`, `useExhaustiveSwitchCases`, `noUnsafePlusOperands`, `useAwaitThenable` and `useArrayFind` — all ten listed in `react-strict`. **Expect new diagnostics on code you have not changed**, particularly floating promises reached through a callback parameter. A Zod-scale performance regression in the same machinery is fixed.
- **Inherited from Biome — recommended rules, so every preset.** Nine fixes reach all six presets including `recommended` and both `-stable` variants, whose rule lists this release does not touch: `noUnusedVariables` (declaration-merging groups, merged namespaces, and Unicode escapes in identifiers now resolve to the same binding), `noUnusedPrivateClassMembers` (compound assignments like `??=` count as a read; destructuring from `this`; private method overloads), `noUselessConstructor` (TypeScript constructors forwarding an argument to `super` are kept), `useAriaPropsForRole` and `useFocusableInteractive` (non-focusable `role="separator"`), `useHeadingContent` (headings rendered via `set:html` / `v-html`), `noDescendingSpecificity`, `noShorthandPropertyOverrides` (`@supports` and nested blocks), and `noDuplicateProperties` (block at-rules).
- **Inherited from Biome — opt-in rules these presets list.** `noInferrableTypes` (tighter diagnostic range), `useExplicitLengthCheck` (no longer reports value-producing `||` fallbacks or optional chains) and `noMisplacedAssertion` (recognises `@fast-check/vitest`'s `test.prop`) are not recommended, so their fixes reach the four presets that list them — `react-strict`, `react-balanced` and both `-stable` — and not `recommended` or `react-recommended`.
- **Inherited from Biome — formatter output changes.** `declare` now prints before accessibility modifiers (`declare private readonly x`), matching Prettier and TypeScript; comments are no longer moved next to a generic's `<`, which produced invalid TypeScript; unquoted CSS URLs beginning with `@` or `!` parse, and escaped whitespace in raw URLs survives formatting. The `useSortedAttributes` assist no longer corrupts JSX attributes when nested elements also need sorting. Formatting is up to ~50% faster, and CSS and JSON linting is faster on large files.
- **Inherited from Biome — parsers.** Astro and Svelte fixes land in files these presets process even though their rules are excluded by design: TypeScript and JSX inside Astro attribute expressions, HTML comments and `is:raw` children in expressions, CRLF multi-line expressions, and Svelte render-tag comment duplication. Astro template suppression comments now suppress HTML lint diagnostics, which reaches consumers here because all six presets set `html.experimentalFullSupportEnabled`.
- **Eleven new nursery rules**, `warn` in `react-strict`: `noBunModules`, `noInvalidFileInputAccept`, `noThisOutsideOfClass`, `noUnmodifiedLoopCondition`, `noUnsafeIframeSandbox`, `noXorAsExponentiation`, `useBetterDomTraversing`, `useFlatMathMinMax`, `useLayeredStyles`, `useModernMathApis`, `useReactNamingConvention`.
- **Three of them are relaxed in `react-balanced`**, established by fixture against 2.5.13 rather than inferred. `useLayeredStyles` → **off**: it reports every style rule *and* every bare `@import` that is not inside a cascade layer — including in CSS Modules, which are scoped by design — and publishes no option to exempt them, so a project that has not adopted `@layer` gets one diagnostic per rule per file. `useReactNamingConvention` → **info**: it fired in a fixture with no React dependency present, so listing it defeats its `react@>=16` gate, and what it enforces is a naming convention on context, id and ref bindings that fires across an entire existing codebase on first adoption. `useBetterDomTraversing` → **info**: a stylistic preference over ordinary DOM code whose fixes are unsafe by the rule's own account. `info` is Biome's own default for both of the latter two.
- **`noBunModules` stays at `warn` in both**, with a caveat worth knowing: it suppresses itself when your `package.json` declares a matching dependency, but only partially. With `bun` declared, `import … from "bun"` goes quiet while `import … from "bun:sqlite"` still reports. A Bun-runtime project will see it on correct code and should turn it off; for the client-side web projects these presets target, a `bun:*` import is a real bug.
- **Excluded: `noSvelteAtHtmlTags`, `noVueDeprecatedScopedSlots`, `useVueBaseImport`** (all nursery). Their only domains are `svelte` and `vue`, which these presets exclude.
- **Counts move asymmetrically.** `react-strict` and `react-balanced` go from 263 to 274 explicit rules (nursery 83 → 94), and balanced relaxations from 19 to 22. Both `-stable` variants are **unchanged — 180 rules, 15 relaxations** — because all eleven additions and all three new relaxations are nursery, which `-stable` strips.
